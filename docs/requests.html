Two items block everything else

Until these land, no amount of other work moves the project forward — attendance cannot be generated at all without shifts, and the size of the custom build cannot be estimated without the policy.

The 23 shift definitions

A1 · Plant managers

Fill in data/out/04-shifts-TO-FILL.xlsx and send it back. Two rows are pre-filled from your own attendance reports; 21 appear in no export you have sent.

  • Start / End — decides which punches belong to the shift at all
  • Crosses midnight? — decides which day the hours land on
  • Break start / end — comes off worked hours, which decide half-day and absent
  • Rotating? — the real question behind Production24hr and Production22hr
  • Half-day / absent thresholds — if identical everywhere, fill row 1 and say so
Why it blocks: Frappe HR generates attendance from punches through the shift. No shift, no attendance, however many punches arrive. And a night shift configured wrong reads as absent two days running — no punch-out on the first, no punch-in on the second.

The attendance policy, as you have it configured

A2 · Factor HR admin

Screenshots are fine — every step of the wizard, per company. Factor HR → Setup → Manage Attendance Policy, and Manage Shift.

  • Late / early forgiveness — Factor HR's own example is "3 times in a month no leave deducted, but on the 4th his half day will be deducted"
  • Deduction target — Loss of Pay, or taken from a paid leave balance
  • Overtime — minimum, maximum, rounding, working vs non-working day, approval
  • Session mode — are pre-break and post-break evaluated separately?
  • Grace periods and the exact half-day / absent thresholds
Why this one matters most: Frappe HR has no equivalent for any of it, so each feature you actually use is custom code. This single screen decides whether that build is a week or two months — and if you don't use frequency forgiveness, a large piece of work disappears.
IT and maintenance

The fingerprint machines

Device inventory

B1

One row per machine:

  • Location — which gate, which company
  • Make and model — must speak the ZK protocol
  • IP address and port — usually 4370
  • Comm key — usually 0 if never set
  • Sends IN/OUT? — many are configured not to
Watch for: a cloud-only or proprietary-SDK device needs a different reader entirely. ZKTeco, eSSL, Realtime and most Indian clones are fine.

A machine to run the bridge

B2

One always-on PC or Raspberry Pi per site — or VPN details, if one box can reach every site.

Why: Frappe Cloud cannot reach a factory LAN, so the bridge has to sit inside your network. It must run whether or not anybody is logged in — one that only runs at login gets found switched off in March, with a month of attendance behind it.
HR

Leave, and where people punch

Coordinates for every gate

C1

Latitude and longitude to six decimals, per punching point, with a name and its company.

Stand at the gate, long-press your position in Google Maps, copy the coordinates. Not from a map pin — a pin lands on the roof and people punch at the door.

Also: how far from each gate a punch should still count. Default 300 m, generous on purpose — a phone against a metal shed reads badly, and refusing somebody who did turn up is the expensive mistake.

Leave types and entitlements

D1–D3

Frappe HR installed five: Casual, Sick, Privilege, Leave Without Pay, Compensatory Off. Your reports show Casual and LWP in use — which of the rest are real?

  • Annual days per type, carry-forward, paid or unpaid
  • Opening balances per person per type, as at a stated date
The date matters more than the number. A balance with no date cannot be reconciled against anything. Nothing has an entitlement set today, so nobody has any balance at all.

Leadership

Six decisions — answers, not files

Each one changes what gets built. None needs any data gathering.

The private bench

F1

Costs nothing extra — Frappe Cloud bills per site and the $25 you already pay is the requirement. It turns on Server Scripts and allows the custom rules app.

It was free of risk when Frappe HR was empty. It isn't any more — 161 employees are on the site now. Still better before daily punches start.

Selfie on punch

F2

Factor HR photographs every mobile punch; this design records coordinates only.

A coordinate proves a phone was near the gate. A photograph proves a person was — which matters exactly where phones get handed to a colleague. Also ~5 MB a day, kept forever unless someone sets a retention rule.

The five optional holidays

F3

All nine are currently one Holiday List, meaning the factory closes on each. If an employee instead chooses which optional days to take, that is a different structure and takes minutes to rebuild.

Manna Tyre UAE

F4

Measured on your live data: all three UAE reps' punches are out by exactly 90 minutes; every Indian rep by zero. Frappe has one timezone per site.

  • Separate site — correct on timezone, weekend, payroll and holidays. Costs a second site for six people.
  • Fix the app, display-only — cheapest; records become consistent but shift windows still run on Indian time.
  • Stay on Factor HR — defer it.
The app bug should be fixed either way. It is wrong today regardless of which option you pick.

How much history to carry

F5

Our suggestion: carry the last complete financial year as read-only history and start live recording at go-live. Importing years of daily attendance produces a table nobody queries and a reconciliation nobody finishes — but gratuity may argue otherwise.

Which Factor HR modules do you actually use?

F6

Your login page advertises ticketing, surveys, performance management and a chatbot. Paying for them is not the same as using them, and building replacements for unused modules is the easiest way to double this project for nothing.
